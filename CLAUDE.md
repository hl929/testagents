## Project Overview

HelloAgents is a Python multi-agent framework built on top of the OpenAI API. It provides multiple agent paradigms (ReAct, FunctionCalling, Reflection, Plan-and-Solve), a native tool system, multi-type memory, context engineering (GSSC pipeline), agent communication protocols (MCP/A2A/ANP), RL training wrappers (SFT/GRPO/PPO), and evaluation tools.

## Common Commands

### Installation

```bash
# Core only (minimal dependencies)
pip install -e .

# With specific optional features
pip install -e ".[search]"       # Tavily/SerpApi search tools
pip install -e ".[memory]"       # Qdrant, Neo4j, spaCy for memory
pip install -e ".[rag]"          # transformers, torch, sentence-transformers for RAG
pip install -e ".[protocols]"    # fastmcp, a2a-sdk for MCP/A2A
pip install -e ".[evaluation]"   # datasets, huggingface_hub, pandas, gradio
pip install -e ".[rl]"           # trl, transformers, torch, peft for RL training
pip install -e ".[all]"          # Everything except evaluation-bfcl
```

Note: `evaluation-bfcl` is intentionally disabled because `bfcl-eval` requires `numpy==1.26.4` which conflicts with the core dependency `numpy>=2.0`. If BFCL evaluation is needed, create an isolated virtual environment and manually install compatible versions.

## High-Level Architecture

### Core Layer (`hello_agents/core/`)

- **`HelloAgentsLLM`** (`core/llm.py`): The unified LLM client. It wraps `openai.OpenAI` and supports 9 providers (openai, deepseek, qwen, modelscope, kimi, zhipu, ollama, vllm, local/custom). It auto-detects the provider from environment variables, API key prefixes, and base URLs. Key methods: `think()` (streaming, default), `invoke()` (non-streaming), `stream_invoke()` (alias).
- **`Agent`** (`core/agent.py`): Abstract base class for all agents. Holds `name`, `llm`, `system_prompt`, `config`, and `_history` (list of `Message`).
- **`Config`** (`core/config.py`): Pydantic-based settings with `from_env()` loader. Defaults to `gpt-3.5-turbo` / `openai`.
- **`Message`** (`core/message.py`): Simple message dataclass used in agent history.

### Agent Paradigms (`hello_agents/agents/`)

All agents inherit from `Agent` and implement `run(input_text: str) -> str`.

- **`SimpleAgent`**: Basic conversational agent with history.
- **`ReActAgent`**: Prompt-based reasoning + acting loop. Parses `Thought:` / `Action:` from LLM output, executes tools via `ToolRegistry.execute_tool()`, and iterates up to `max_steps`.
- **`FunctionCallAgent`**: Uses OpenAI native function calling. Builds tool schemas from `ToolRegistry`, calls `_invoke_with_tools()` on the underlying OpenAI client, executes tool calls, and loops up to `max_tool_iterations`. Supports both `Tool` objects and function-based tools.
- **`ReflectionAgent`**: Iterative self-improvement loop (generate -> reflect -> refine) with configurable prompt templates per stage.
- **`PlanAndSolveAgent`**: Decomposes problems into plans and executes step-by-step.
- **`ToolAwareSimpleAgent`**: Simple agent that is aware of available tools.

### Tool System (`hello_agents/tools/`)

- **`Tool`** (`tools/base.py`): Abstract base for all tools. Supports two modes:
  1. Single-function tool: subclass and implement `run()` and `get_parameters()`.
  2. Expandable tool: set `expandable=True` and use `@tool_action` decorator on methods. `get_expanded_tools()` auto-generates sub-tools via `AutoGeneratedTool`, which introspects method signatures and docstrings to build `ToolParameter` schemas.
- **`ToolRegistry`** (`tools/registry.py`): Registers `Tool` objects (with optional auto-expansion) or plain functions. Provides `execute_tool()`, `get_tools_description()`, and `get_all_tools()`.
- **`global_registry`**: Module-level singleton registry.
- **`ToolChain` / `ToolChainManager`** (`tools/chain.py`): Sequential tool execution chains.
- **`AsyncToolExecutor`** (`tools/async_executor.py`): Parallel async tool execution.
- Built-in tools live in `tools/builtin/` (search, calculator, memory, RAG, evaluation, MCP wrapper).

### Memory System (`hello_agents/memory/`)

- **`BaseMemory`** (`memory/base.py`): Abstract base defining `add()`, `retrieve()`, `update()`, `remove()`. Uses `MemoryItem` (Pydantic) and `MemoryConfig`.
- **Memory Types** (`memory/types/`): `WorkingMemory`, `EpisodicMemory`, `SemanticMemory`, `PerceptualMemory`. Each implements `BaseMemory` with its own storage/retrieval strategy.
- **`MemoryManager`** (`memory/manager.py`): Unified interface managing multiple memory types. Supports auto-classification of memory type by content keywords, importance scoring, forgetting strategies, and consolidation between types (e.g., working -> episodic).
- **Embedding** (`memory/embedding.py`): Embedding utilities for vector retrieval.

### Context Engineering (`hello_agents/context/`)

- **`ContextBuilder`** (`context/builder.py`): Implements the GSSC pipeline:
  1. **Gather**: collects system instructions, memory (task state + related), RAG results, and recent conversation history.
  2. **Select**: scores packets by relevance (keyword overlap) + recency (exponential decay), filters by `min_relevance`, and fills within token budget.
  3. **Structure**: assembles packets into a structured template with sections `[Role & Policies]`, `[Task]`, `[State]`, `[Evidence]`, `[Context]`, `[Output]`.
  4. **Compress**: truncates by line if over token budget.
- Uses `tiktoken` (cl100k_base) for token counting.

### Protocols (`hello_agents/protocols/`)

- **`ProtocolType`** (`protocols/base.py`): Enum for MCP, A2A, ANP. The `Protocol` base class is conceptual; actual implementations are independent.
- **MCP** (`protocols/mcp/`): `MCPClient` wraps `fastmcp.Client` and supports multiple transports (memory, stdio, HTTP, SSE). Auto-detects transport from server source type (FastMCP instance, `.py` path, URL, command list, or config dict). Exposes `list_tools()`, `call_tool()`, `list_resources()`, `read_resource()`, `list_prompts()`, `get_prompt()`.
- **A2A** (`protocols/a2a/`): `A2AServer` and related classes built on `a2a-sdk`.
- **ANP** (`protocols/anp/`): Conceptual implementation for service discovery, network topology, and load balancing.

### RL Training (`hello_agents/rl/`)

Wraps TRL (`trl`) trainers with a unified interface:

- **`SFTTrainerWrapper`** (`rl/trainers.py`): Supervised fine-tuning via `trl.SFTTrainer`. Handles model/tokenizer loading, `SFTConfig`, and `DetailedLoggingCallback`.
- **`GRPOTrainerWrapper`**: Group Relative Policy Optimization via `trl.GRPOTrainer`. Requires a `reward_fn`.
- **`PPOTrainerWrapper`**: Placeholder (not yet implemented); recommends GRPO instead.
- **`TrainingConfig`** (`rl/utils.py`): Shared configuration dataclass.
- **`rl/datasets.py`**: Dataset preparation utilities.
- **`rl/rewards.py`**: Reward function implementations.

### Evaluation (`hello_agents/evaluation/`)

Built-in evaluation tools:

- **`BFCLEvaluationTool`** (`tools/builtin/bfcl_evaluation_tool.py`): Wrapper for BFCL ( Berkeley Function Calling Leaderboard) evaluation. Must be run in an isolated environment due to numpy version conflicts.
- **`GAIAEvaluationTool`** (`tools/builtin/gaia_evaluation_tool.py`): GAIA benchmark evaluation.
- **`LLMJudgeTool`** (`tools/builtin/llm_judge_tool.py`): LLM-as-judge scoring.

## Configuration & Environment

The framework is configured primarily through environment variables / `.env`:

- **Generic**: `LLM_MODEL_ID`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_TIMEOUT`
- **Provider-specific**: `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `DASHSCOPE_API_KEY`, `MODELSCOPE_API_KEY`, `KIMI_API_KEY` / `MOONSHOT_API_KEY`, `ZHIPU_API_KEY` / `GLM_API_KEY`, `OLLAMA_API_KEY` / `OLLAMA_HOST`, `VLLM_API_KEY` / `VLLM_HOST`
- **Search**: `TAVILY_API_KEY`, `SERPAPI_API_KEY`

`HelloAgentsLLM` auto-detects provider using a priority cascade: specific env vars -> API key format -> base URL domain -> fallback to `auto`.

## Key Design Patterns

- **Tool Expandability**: Tools can expose multiple sub-tools either manually or automatically via `@tool_action`. The registry handles expansion via `auto_expand=True`. This is used heavily for MCP wrapper tools and memory tools.
- **Agent History**: All agents maintain `_history` as a list of `Message` objects. `FunctionCallAgent` and `ReActAgent` additionally maintain execution-specific state (tool call loops, step history).
- **Streaming vs Non-Streaming**: `HelloAgentsLLM.think()` is streaming (default, prints to stdout); `invoke()` is non-streaming and returns full text. Agents generally use `invoke()` internally; only `SimpleAgent` uses `think()` for direct streaming output.
- **Prompt Templates**: ReActAgent, ReflectionAgent, and PlanAndSolveAgent support custom prompt templates. Default templates are in their respective modules (e.g., `DEFAULT_REACT_PROMPT` in `react_agent.py`).
- **Pydantic Everywhere**: Config, memory items, and tool parameters use Pydantic v2 models.
- **Lazy Imports**: Optional heavy dependencies (transformers, trl, fastmcp, etc.) are imported lazily inside methods to avoid hard failures when only core is installed.

## File Structure Notes

- `hello_agents/` is the main package. `pyproject.toml` configures `setuptools` to include `hello_agents*` only (excluding `tests*`, `examples*`, `docs*`).
- `setup.py` exists for backward compatibility but delegates to `pyproject.toml`.
- Examples are numbered by chapter (`chapter07_*` through `chapter11_*`) corresponding to tutorial progression.
- The codebase uses Chinese for user-facing strings, comments, and docstrings. Keep this convention.
