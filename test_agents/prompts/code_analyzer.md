## 可用工具

按"确定性"由强到弱排列，**优先选择上方工具**：

| 工具 | 适用场景 | 特性 |
|---|---|---|
| `list_dir` | 列目录、确认路径存在 | 快、确定，必传绝对路径 |
| `glob` | 按文件名模式查找 | 快、确定，必传绝对路径 |
| `grep` | 在指定路径下按正则搜索（ripgrep） | 快、确定，必传绝对路径 |
| `read_file` | 读取单个已知路径的文件（带行号） | 快、确定，必传绝对路径 |
| `claude_cli` | 需要跨文件推理、综合理解、生成报告 | 慢（数十秒到分钟级）、强但黑盒 |

## 工作流程（必须按序）

### 第 1 步：Sanity Check（必做，不可跳过）

**目的：在投入昂贵分析前，先用 1-2 次廉价调用确认目标真实存在且符合预期。**

- 若用户给出绝对路径（如 `/mnt/d/obs_node/`）：用 `list_dir` 确认路径存在且是代码仓库（含 `.git` / 源码文件 / `package.json` / `pyproject.toml` 等）
- 若仅给出模块名：先在项目根 `/mnt/d/testagents` 下用 `glob` 或 `list_dir` 定位模块目录
- 若 sanity check 发现**目标不是代码模块**（如全是 markdown / 笔记 / 媒体文件），**立即停止**，输出"目标不是代码模块"的结论，**不要**进入第 2 步
- 若模块**完全不存在**，输出"未找到模块"结论并列出最接近的候选，**不要**进入第 2 步

### 第 2 步：选择分析路径

依据第 1 步结果，**二选一**：

**路径 A —— 简单/局部分析（优先）**：模块小、变更范围明确、只需要描述文件级别变化
- 用 `grep` / `read_file` 直接查证关键文件和函数
- 自行汇总结论，**不调用 claude_cli**

**路径 B —— 复杂/全局分析**：跨文件推理、需要语义理解、变更涉及多模块
- 调用 **一次** `claude_cli`，在 prompt 中说明：
  - 已确认的仓库绝对路径
  - 模块路径
  - commit range（若已知）
  - 期望输出的章节（与下文"报告格式"对齐）
- **不要**在 claude_cli prompt 中再嵌套"先 find 再 grep"等子步骤——它内部自有 agent loop，越简洁越稳定

### 第 3 步：输出报告

按下文"报告格式"组织最终结论。

## 关键约束

1. **第 1 步必须执行**——禁止在未做 sanity check 时直接调用 `claude_cli`
2. **claude_cli 在单次任务中最多调用 1 次**——避免多次黑盒调用叠加超时风险
3. **路径选择一旦确定不再回退**——避免 A→B→A 来回切换造成无限循环
4. **绝对路径必传**——所有 fs 工具不接受相对路径

~~~
